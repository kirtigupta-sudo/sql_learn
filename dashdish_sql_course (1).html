Getting started · 1

What is SQL?

SQL (Structured Query Language) is the standard language for creating, reading, updating, and deleting data in relational databases such as MySQL, PostgreSQL, Oracle, and SQL Server.

Relational data lives in tables: rows are records, columns are attributes. A delivery platform might store customers, restaurants, couriers, orders, menu items, and order lines in related tables. SQL statements are commonly grouped into five families:

DDL

Data Definition Language

CREATE, ALTER, DROP, TRUNCATE, RENAME define or change structures.

DML

Data Manipulation Language

INSERT, UPDATE, DELETE change table rows.

DQL

Data Query Language

SELECT reads rows.

TCL

Transaction Control Language

COMMIT, ROLLBACK, SAVEPOINT manage transactions.

DCL

Data Control Language

GRANT, REVOKE manage permissions.

Dialect note: this course targets MySQL 8+. Core SQL ideas transfer, but syntax and behavior vary across database engines.

DDL · 3

Create a schema and tables

In MySQL, a database is also commonly called a schema. Create it, select it with USE, then create tables with columns, data types, defaults, and constraints.

DDL · create database and core tables
DROP DATABASE IF EXISTS dashdish;
CREATE DATABASE dashdish
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_0900_ai_ci;
USE dashdish;

CREATE TABLE customers (
  customer_id INT NOT NULL,
  customer_name VARCHAR(80) NOT NULL,
  city VARCHAR(60) NOT NULL,
  signup_date DATE NOT NULL,
  loyalty_tier VARCHAR(12) NOT NULL DEFAULT 'standard',
  PRIMARY KEY (customer_id)
);

CREATE TABLE restaurants (
  restaurant_id INT NOT NULL,
  restaurant_name VARCHAR(100) NOT NULL,
  cuisine VARCHAR(40) NOT NULL,
  city VARCHAR(60) NOT NULL,
  opened_on DATE,
  PRIMARY KEY (restaurant_id)
);

CREATE TABLE couriers (
  courier_id INT NOT NULL,
  courier_name VARCHAR(80) NOT NULL,
  vehicle_type VARCHAR(20) NOT NULL,
  home_city VARCHAR(60) NOT NULL,
  PRIMARY KEY (courier_id)
);

Create the transactional tables

DDL · menu, orders, and order lines
CREATE TABLE menu_items (
  item_id INT NOT NULL,
  restaurant_id INT NOT NULL,
  item_name VARCHAR(100) NOT NULL,
  category VARCHAR(30) NOT NULL,
  price DECIMAL(7,2) NOT NULL,
  rating DECIMAL(2,1),
  is_available BOOLEAN NOT NULL DEFAULT TRUE,
  PRIMARY KEY (item_id)
);

CREATE TABLE orders (
  order_id INT NOT NULL,
  customer_id INT NOT NULL,
  restaurant_id INT NOT NULL,
  courier_id INT,
  order_date DATETIME NOT NULL,
  status VARCHAR(20) NOT NULL,
  delivery_fee DECIMAL(6,2) NOT NULL DEFAULT 0,
  PRIMARY KEY (order_id)
);

CREATE TABLE order_items (
  order_item_id INT NOT NULL,
  order_id INT NOT NULL,
  item_id INT NOT NULL,
  quantity INT NOT NULL,
  unit_price DECIMAL(7,2) NOT NULL,
  PRIMARY KEY (order_item_id)
);

Data types: INT is a whole number; VARCHAR(n) stores variable-length text; DATE stores a calendar date; DATETIME stores date and time; DECIMAL(p,s) stores exact numeric values. MySQL BOOLEAN is a synonym for TINYINT(1).

DDL · 5

ALTER TABLE: modify structures

ALTER TABLE adds, modifies, renames, or removes columns and constraints.

Add a column

DDL · add optional email
ALTER TABLE customers
ADD COLUMN email VARCHAR(255) NULL;

Modify a column

DDL · widen a name column
ALTER TABLE customers
MODIFY COLUMN customer_name VARCHAR(120) NOT NULL;

Rename a column

DDL · MySQL 8 syntax
ALTER TABLE customers
RENAME COLUMN loyalty_tier TO membership_tier;

Older MySQL versions use CHANGE COLUMN and require the full new column definition. Plan schema changes around dependent applications, defaults, nullability, indexes, and migrations.

DDL · 6

DROP, TRUNCATE, and RENAME

DROP

Remove object and data

DROP TABLE removes the table definition and rows.

TRUNCATE

Remove all rows

Keeps structure but empties the table; no WHERE filter.

RENAME

Rename an object

Changes a table name without changing its rows.

DDL · examples
CREATE TABLE scratch_orders LIKE orders;
INSERT INTO scratch_orders SELECT * FROM orders;
TRUNCATE TABLE scratch_orders;
RENAME TABLE scratch_orders TO archived_orders;
DROP TABLE archived_orders;

DELETE FROM table is DML and may use WHERE. TRUNCATE is DDL-like in MySQL, commonly implicitly commits, and resets auto-increment. DROP removes the object. Verify the environment before destructive commands.

DDL · 7

Add and remove constraints

Constraints enforce data quality. Existing rows must satisfy a new constraint before it can be added.

DDL · check, unique, and remove
ALTER TABLE menu_items
ADD CONSTRAINT chk_menu_price_nonnegative
CHECK (price >= 0);

ALTER TABLE menu_items
ADD CONSTRAINT chk_menu_rating_range
CHECK (rating IS NULL OR rating BETWEEN 0 AND 5);

ALTER TABLE customers
ADD CONSTRAINT uq_customer_email UNIQUE (email);

ALTER TABLE menu_items
DROP CHECK chk_menu_rating_range;

ALTER TABLE customers
DROP INDEX uq_customer_email;

MySQL backs unique constraints with indexes. In current MySQL releases, use DROP CHECK for check constraints and DROP INDEX for the associated unique index.

DDL · 8

Modify and drop columns

DDL · modify, add, remove
ALTER TABLE restaurants
MODIFY COLUMN restaurant_name VARCHAR(150) NOT NULL;

ALTER TABLE restaurants
ADD COLUMN phone VARCHAR(25) NULL;

ALTER TABLE restaurants
DROP COLUMN phone;
Data-loss warning: dropping a column deletes its values. Modifying types may truncate, reject, or transform existing values. Inspect and back up data before migrations.
DDL / DML · 9

AUTO_INCREMENT: generated IDs

With manually assigned IDs, each insert supplies the ID. With AUTO_INCREMENT, MySQL generates one when the column is omitted or set to NULL.

DDL · generated primary key
CREATE TABLE app_customers (
  customer_id INT NOT NULL AUTO_INCREMENT,
  customer_name VARCHAR(80) NOT NULL,
  PRIMARY KEY (customer_id)
);

INSERT INTO app_customers (customer_name)
VALUES ('Sample customer one'), ('Sample customer two');

SELECT LAST_INSERT_ID();
  • The auto-increment column must be indexed and is commonly the primary key.
  • IDs usually rise but are not gap-free; failures, rollbacks, and deletions can leave gaps.
  • LAST_INSERT_ID() returns the first generated ID from the latest insert on the same connection.
  • Explicitly inserting a larger ID can change the next generated value.
  • Use surrogate IDs for relationships and separate columns for meaningful business numbers.
DQL · 10

SELECT: read rows

DQL · select columns
SELECT * FROM customers;

SELECT customer_id, customer_name, city
FROM customers;

SELECT item_name, price, price * 1.10 AS price_with_tax
FROM menu_items;

SELECT * is useful for quick inspection. Explicit column lists are more stable, readable, and efficient in application queries.

DQL · 11

WHERE: filter rows

DQL · comparison and Boolean filters
SELECT item_name, price, rating
FROM menu_items
WHERE price > 10 AND is_available = TRUE;

SELECT customer_name, city, loyalty_tier
FROM customers
WHERE city = 'Portland'
   OR loyalty_tier = 'gold';

Comparison operators include =, <> / !=, <, <=, >, and >=. Quote text and date literals.

DQL · 12

Operators, precedence, and NULL

DQL · BETWEEN, IN, LIKE, NULL
SELECT item_name, category, price
FROM menu_items
WHERE price BETWEEN 8 AND 15
  AND category IN ('main', 'side');

SELECT restaurant_name FROM restaurants
WHERE restaurant_name LIKE 'C%';

SELECT order_id FROM orders
WHERE courier_id IS NULL;

BETWEEN includes endpoints. LIKE uses % for any-length text and _ for one character. NULL means missing or unknown; test with IS NULL.

AND, OR, NOT and parentheses

DQL · explicit precedence
SELECT customer_name, city, loyalty_tier
FROM customers
WHERE (city = 'Portland' OR city = 'Seattle')
  AND loyalty_tier <> 'standard';

AND has higher precedence than OR. Parentheses make intent clear. SQL uses TRUE, FALSE, and UNKNOWN logic; comparisons involving NULL commonly yield UNKNOWN. COALESCE(value, fallback) returns the first non-NULL value.

DQL · 13

Aggregate functions

DQL · common aggregates
SELECT COUNT(*) AS item_rows,
       COUNT(rating) AS rated_items,
       COUNT(DISTINCT category) AS categories,
       AVG(price) AS average_price,
       MIN(price) AS lowest_price,
       MAX(price) AS highest_price,
       SUM(price) AS sum_of_item_prices
FROM menu_items;

COUNT(*) counts rows; COUNT(column) ignores NULL; COUNT(DISTINCT column) counts distinct non-NULL values. SUM and AVG ignore NULL. Menu price totals are not sales revenue; sales require quantities from order lines.

DQL · 14

GROUP BY and HAVING

GROUP BY partitions rows for aggregation. WHERE filters rows before grouping; HAVING filters groups after aggregation.

DQL · aggregate by restaurant
SELECT restaurant_id, COUNT(*) AS item_count,
       AVG(price) AS average_price
FROM menu_items
GROUP BY restaurant_id
HAVING COUNT(*) >= 1
ORDER BY average_price DESC;

Conditional aggregation

DQL · count status categories
SELECT restaurant_id, COUNT(*) AS all_orders,
 SUM(CASE WHEN status='delivered' THEN 1 ELSE 0 END) AS delivered,
 SUM(CASE WHEN status='cancelled' THEN 1 ELSE 0 END) AS cancelled
FROM orders GROUP BY restaurant_id;

In strict SQL, nonaggregate selected expressions should be grouped or functionally dependent on grouped keys. MySQL’s ONLY_FULL_GROUP_BY helps catch ambiguous queries.

DQL · 15

Joins: connect related rows

DQL · order and customer details
SELECT o.order_id, c.customer_name,
       r.restaurant_name, o.status
FROM orders o
JOIN customers c ON c.customer_id = o.customer_id
JOIN restaurants r ON r.restaurant_id = o.restaurant_id
ORDER BY o.order_id;

The inner joins omit order 1015 because customer 999 is absent. Use aliases and qualify ambiguous columns.

Join at the right grain

DQL · order line detail
SELECT o.order_id, oi.order_item_id, mi.item_name,
       oi.quantity, oi.unit_price
FROM orders o
JOIN order_items oi ON oi.order_id = o.order_id
LEFT JOIN menu_items mi ON mi.item_id = oi.item_id
ORDER BY o.order_id, oi.order_item_id;

Orders with several line items appear several times. Joining order-level fees into this result repeats the fee for every line. Aggregate at the correct level or pre-aggregate line items.

DQL · 16

Join types and combinations

INNER JOIN

Only matching rows on both sides.

LEFT JOIN

All left rows; unmatched right columns become NULL.

RIGHT JOIN

All right rows; often rewritten as LEFT JOIN by swapping tables.

FULL OUTER JOIN

All matches and unmatched rows from both sides; MySQL has no native syntax.

CROSS JOIN

Every pair; 15 customers × 15 restaurants gives 225 rows.

Self join

A table joined to itself using different aliases.

DQL · unmatched customers
SELECT c.customer_id, c.customer_name
FROM customers c LEFT JOIN orders o
  ON o.customer_id = c.customer_id
WHERE o.order_id IS NULL;
DQL · emulate FULL OUTER JOIN
SELECT c.customer_id,c.customer_name,o.order_id
FROM customers c LEFT JOIN orders o ON o.customer_id=c.customer_id
UNION ALL
SELECT c.customer_id,c.customer_name,o.order_id
FROM orders o LEFT JOIN customers c ON c.customer_id=o.customer_id
WHERE c.customer_id IS NULL;

UNION removes duplicate rows; UNION ALL preserves them. Corresponding query columns must align in order and compatible type.

DQL · 17

Subqueries

A subquery is a query inside another query. It may return a scalar value, list, result table, or existence test.

DQL · scalar subquery
SELECT item_name, price
FROM menu_items
WHERE price > (SELECT AVG(price) FROM menu_items);
DQL · IN and EXISTS
SELECT customer_id, customer_name
FROM customers
WHERE customer_id IN (SELECT customer_id FROM orders);

SELECT c.customer_id, c.customer_name
FROM customers c
WHERE EXISTS (SELECT 1 FROM orders o
              WHERE o.customer_id=c.customer_id);

A scalar subquery must return one value. EXISTS tests for at least one matching row. Prefer NOT EXISTS to NOT IN when the inner result might contain NULL.

DQL · 18

CTEs: name intermediate results

DQL · customer spend with CTEs
WITH order_food_totals AS (
  SELECT order_id, SUM(quantity * unit_price) AS food_total
  FROM order_items GROUP BY order_id
), customer_totals AS (
  SELECT o.customer_id, COUNT(*) AS order_count,
         SUM(t.food_total + o.delivery_fee) AS spend
  FROM orders o JOIN order_food_totals t ON t.order_id=o.order_id
  GROUP BY o.customer_id
)
SELECT c.customer_name, ct.order_count, ct.spend
FROM customer_totals ct JOIN customers c
  ON c.customer_id=ct.customer_id
ORDER BY ct.spend DESC;

A CTE exists for one statement and can clarify multi-step queries. It is not automatically faster than a subquery.

Recursive CTE

DQL · generate a date sequence
WITH RECURSIVE days AS (
  SELECT DATE('2025-09-01') AS day
  UNION ALL
  SELECT day + INTERVAL 1 DAY
  FROM days WHERE day < '2025-09-07'
)
SELECT day FROM days;

Recursive CTEs have an anchor member and recursive member. Always include a termination condition.

DQL · 19

Window functions

Window functions calculate across related rows while keeping individual rows in the result.

DQL · ROW_NUMBER, RANK, DENSE_RANK
SELECT item_name, rating,
 ROW_NUMBER() OVER (ORDER BY rating DESC, item_id) AS row_num,
 RANK() OVER (ORDER BY rating DESC) AS rating_rank,
 DENSE_RANK() OVER (ORDER BY rating DESC) AS dense_rank
FROM menu_items WHERE rating IS NOT NULL
ORDER BY rating DESC,item_id;
RatingsRANKDENSE_RANK
4.9, 4.91, 11, 1
4.8, 4.83, 32, 2
4.7, 4.75, 53, 3

ROW_NUMBER is unique; RANK leaves gaps after ties; DENSE_RANK does not. PARTITION BY restaurant_id restarts rankings for each restaurant.

DQL · running total and LAG
WITH order_totals AS (
 SELECT o.order_id,o.customer_id,o.order_date,
        SUM(oi.quantity*oi.unit_price)+o.delivery_fee AS total
 FROM orders o JOIN order_items oi ON oi.order_id=o.order_id
 GROUP BY o.order_id,o.customer_id,o.order_date,o.delivery_fee
)
SELECT customer_id,order_id,order_date,total,
 SUM(total) OVER (PARTITION BY customer_id
   ORDER BY order_date,order_id
   ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS running_spend,
 LAG(total) OVER (PARTITION BY customer_id
   ORDER BY order_date,order_id) AS previous_order_total
FROM order_totals;

OVER defines the window; PARTITION BY groups it; ORDER BY sequences it; the frame defines included rows. LAG and LEAD access neighboring rows.

DQL · 20

CASE, NULL, and conditional logic

DQL · classify delivery fees
SELECT order_id, delivery_fee,
 CASE WHEN delivery_fee = 0 THEN 'Free'
      WHEN delivery_fee < 3 THEN 'Low'
      ELSE 'Standard' END AS fee_band
FROM orders;

CASE can be used in SELECT, ORDER BY, and aggregate expressions. NULL represents missing or unknown data and is not equal to itself. Use IS NULL. Aggregates generally ignore NULL. A fallback value should not be mistaken for a real key.

DML · 21

INSERT, UPDATE, DELETE

DML · insert with explicit columns
INSERT INTO menu_items
 (item_id,restaurant_id,item_name,category,price,rating,is_available)
VALUES (116,1,'Seasonal grain bowl','main',14.25,4.6,TRUE);
DML · inspect and update
SELECT item_id,item_name,price FROM menu_items
WHERE restaurant_id=1 AND category='side';

UPDATE menu_items SET price=price*1.05
WHERE restaurant_id=1 AND category='side';
DML · delete filtered rows
DELETE FROM orders
WHERE status='cancelled'
  AND order_date < '2025-01-01';
UPDATE or DELETE without WHERE affects every row. Preview with SELECT and verify affected-row counts. Joined modification syntax varies by database.
TCL · 22

Transactions: COMMIT, ROLLBACK, SAVEPOINT

Transactions group changes into one unit of work when using a transactional engine such as InnoDB.

TCL · savepoint example
START TRANSACTION;
UPDATE menu_items SET price=price*0.95
WHERE restaurant_id=1;
SAVEPOINT after_discount;
UPDATE orders SET delivery_fee=0
WHERE status='delivered';
ROLLBACK TO SAVEPOINT after_discount;
COMMIT;

The earlier price change remains; the later delivery-fee change is undone. ROLLBACK undoes uncommitted work; COMMIT keeps it. MySQL DDL often implicitly commits.

Atomicity

All work succeeds or is undone.

Consistency

Rules and constraints remain satisfied.

Isolation

Concurrent work follows isolation rules.

Durability

Committed changes persist.

DCL · 23

GRANT and REVOKE

DCL controls access to database objects. Apply least privilege: give accounts only the access needed for their task.

DCL · create read-only account
CREATE USER 'dashdish_reader'@'localhost'
IDENTIFIED BY 'Use-a-unique-secret-from-a-secret-manager';
GRANT SELECT ON dashdish.*
TO 'dashdish_reader'@'localhost';
SHOW GRANTS FOR 'dashdish_reader'@'localhost';
REVOKE SELECT ON dashdish.*
FROM 'dashdish_reader'@'localhost';
Example credentials are placeholders, not production secrets. Account syntax depends on host, version, and deployment settings.
DDL · 24

Constraints and referential integrity

A primary key identifies a row. A foreign key ensures a referenced record exists. Find the intentionally unmatched references before adding foreign keys.

DQL · find orphan references
SELECT o.order_id,o.customer_id
FROM orders o LEFT JOIN customers c
ON c.customer_id=o.customer_id
WHERE c.customer_id IS NULL;

SELECT oi.order_item_id,oi.item_id
FROM order_items oi LEFT JOIN menu_items m
ON m.item_id=oi.item_id
WHERE m.item_id IS NULL;

After repairing/removing invalid rows, add constraints:

DDL · add foreign keys after cleanup
ALTER TABLE orders ADD CONSTRAINT fk_orders_customer
FOREIGN KEY (customer_id) REFERENCES customers(customer_id);
ALTER TABLE orders ADD CONSTRAINT fk_orders_restaurant
FOREIGN KEY (restaurant_id) REFERENCES restaurants(restaurant_id);
ALTER TABLE orders ADD CONSTRAINT fk_orders_courier
FOREIGN KEY (courier_id) REFERENCES couriers(courier_id);
ALTER TABLE order_items ADD CONSTRAINT fk_order_items_order
FOREIGN KEY (order_id) REFERENCES orders(order_id);
ALTER TABLE order_items ADD CONSTRAINT fk_order_items_menu
FOREIGN KEY (item_id) REFERENCES menu_items(item_id);

Foreign key columns need compatible types and indexes. Decide carefully whether deletes should be restricted, cascaded, or set a nullable child key to NULL.

Performance · 25

Indexes and EXPLAIN

Indexes can improve lookups, joins, sorting, and uniqueness checks, while consuming storage and adding work to writes.

DDL · create indexes
CREATE INDEX idx_orders_customer_date
ON orders (customer_id, order_date);
CREATE INDEX idx_orders_restaurant_status
ON orders (restaurant_id, status);
CREATE INDEX idx_menu_restaurant_rating
ON menu_items (restaurant_id, rating);

Composite indexes are ordered by leading columns. Measure workload before adding indexes.

Inspect query plan
EXPLAIN
SELECT order_id,order_date FROM orders
WHERE customer_id=3 ORDER BY order_date;

EXPLAIN ANALYZE
SELECT order_id,order_date FROM orders
WHERE customer_id=3 ORDER BY order_date;

EXPLAIN ANALYZE executes the query. Use care with expensive queries on production data.

Delivered-order counts for every restaurant

SELECT r.restaurant_name,COUNT(o.order_id) AS delivered_orders
FROM restaurants r LEFT JOIN orders o
ON o.restaurant_id=r.restaurant_id AND o.status='delivered'
GROUP BY r.restaurant_id,r.restaurant_name
ORDER BY delivered_orders DESC;

Count the nullable joined key rather than COUNT(*) to show zero for unmatched restaurants.

Top two ratings per restaurant

WITH ranked AS (
 SELECT restaurant_id,item_name,rating,
 DENSE_RANK() OVER(PARTITION BY restaurant_id ORDER BY rating DESC) AS rnk
 FROM menu_items WHERE rating IS NOT NULL
)
SELECT * FROM ranked WHERE rnk <= 2;
